# 설문 입력 가드레일 및 유효성 검증

## 1. 목적

개인정보의 과도한 입력, 형식이 서로 다른 응답, 날짜·숫자 오입력과 API 직접 호출을 통한 검증 우회를 줄인다. 화면 검증은 빠른 안내를 담당하고 서버 검증은 최종 저장 경계를 담당한다.

## 2. 적용 흐름

```text
입력 컨트롤 제한 → 단계 이동 전 검증 → 서버 초안 검증 → 서버 최종제출 검증 → 정규화 저장
```

브라우저 검증을 통과해도 서버 규칙을 통과하지 못하면 PostgreSQL에 저장하지 않는다. 최종 제출에서는 모든 설문 단계를 다시 검사하므로 사이드 메뉴로 단계를 건너뛰어도 누락 응답을 제출할 수 없다.

## 3. 개인정보 가드레일

| 항목 | 규칙 |
|---|---|
| 연구대상자 식별번호 | 영문 대문자, 숫자, `-`, `_`만 허용, 최대 40자 |
| 이름·주민등록번호 | 입력 안내에서 금지하고 주민등록번호 형태는 서버에서 거절 |
| 연락처 | 국내 전화번호 9~11자리, 저장 시 하이픈 형식 통일 |
| 통화 가능 시간 | 자유입력 대신 네 개 시간 구간 중 선택 |
| 기타 거주지역 | 권역 수준만 입력하도록 안내, 상세 주소 금지 |
| 자유서술 | 이름·연락처·병원명 등 직접식별정보를 제외하도록 안내 |
| 브라우저 임시저장 | 영구 `localStorage` 대신 탭 종료 시 정리되는 `sessionStorage` 사용 |

서버 초안에는 개인정보와 건강정보가 저장되므로 운영 전 애플리케이션 암호화, 관리자 인증, 접근 감사로그와 보관·파기 정책이 별도로 필요하다.

## 4. 형식 및 범위

| 항목 | 허용 규칙 |
|---|---|
| 조사일 | 오늘 이전 또는 오늘 |
| 생년월일 | 1900-01-01부터 오늘, 조사일 기준 만 나이 계산 |
| 만 55세 이상 | 생년월일에서 계산한 결과와 응답이 일치해야 함 |
| 키 | 100~220cm, 소수점 첫째 자리 |
| 체중 | 20~250kg, 소수점 첫째 자리 |
| 폐경 나이 | 20~80세 정수 또는 잘 모르겠음 |
| 호르몬 치료기간 | 0~60년과 0~11개월, 합계 1개월 이상 또는 잘 모르겠음 |
| 최초 제품 섭취 | 1900년부터 조사일 사이 |
| 제품 총 섭취기간 | 0~1,200개월 정수 |
| 제품 평균 섭취빈도 | 사전 정의된 여덟 개 구간 중 선택 |
| 구매·수령 이력 | 조사월 이후 금지, 시작월이 종료월보다 늦을 수 없음 |
| 골절 총 건수 | 1~99건 정수 또는 잘 모르겠음 |
| 골절 발생 연월 | 조사일 이전 24개월 범위 |
| 제품·골절 반복 | 제품 최대 20개, 골절 상세 최대 3건 |
| 첨부파일 | JPG·PNG·WEBP, 파일당 10MB, 분류별 최대 10개 |

키·체중·치료기간·제품 최대 개수 등 일부 범위는 오입력과 과도한 요청을 막기 위한 `PoC 기준`이다. 실제 연구계획서와 데이터관리계획에 따라 연구책임자가 확정해야 한다.

## 5. 자유입력 길이

| 항목 | 최대 길이 |
|---|---:|
| 조사 방법·지역·학력·소득·직업 기타 | 100자 |
| 제품명 | 200자 |
| 제품 섭취 기타 이유 | 500자 |
| 중단·재섭취 이력 | 2,000자 |

제어문자와 줄바꿈은 한 줄 입력에서 허용하지 않는다. 중단·재섭취 이력만 줄바꿈을 허용한다.

## 6. 정규화 저장

- 식별번호는 대문자로 저장한다.
- 전화번호는 국내 전화번호 하이픈 형식으로 저장한다.
- 한 줄 자유입력은 앞뒤 공백과 연속 공백을 정리한다.
- 여러 줄 입력은 줄바꿈을 `LF`로 통일한다.
- 화면에서 선택하지 않은 조건부 항목은 서버에서 `null`로 제거한다.

## 7. 운영 확정이 필요한 정책

- 해외 전화번호 허용 여부
- 연구대상자 식별번호의 실제 기관 규칙
- 숫자 범위와 반복 항목 최대 개수
- 연락 가능 시간 구간
- 브라우저 종료 후 임시작성 복구 필요 여부
- 개인정보 암호화 키, 보관기간과 파기 방식

정책이 확정되면 화면 상수와 서버 허용 목록을 함께 변경하고 회귀 테스트를 갱신한다.
