# 관리자 설문 편집·현황 대시보드 제안

## 1. 현재 상황

현재 설문 Ver. 2.4는 React 컴포넌트, TypeScript 타입, Spring 검증 코드와 PostgreSQL 컬럼에 문항이 고정되어 있다. 따라서 문구·선택지·문항 순서를 바꾸려면 코드를 수정하고 다시 배포해야 한다.

현재 수집 데이터만으로 제출 건수, 제출률, 연령대, 지역, 제품 섭취 경험, 골절 경험, 식품 섭취빈도 등의 집계는 가능하다. 반면 단계별 이탈률은 마지막 완료 단계나 단계 이벤트를 저장하지 않으므로 정확히 계산할 수 없다.

## 2. 목표

- 관리자가 문항 문구, 설명, 필수 여부, 선택지, 표시 순서를 편집한다.
- 이미 배포된 설문과 수집된 답변은 변경하지 않고 설문 버전별로 보존한다.
- 개인 응답 노출보다 집계와 원인 분석을 우선하는 현황 화면을 제공한다.
- 소수 집단 재식별, 무단 다운로드와 임의 설문 변경을 방지한다.

## 3. 핵심 정책

설문 생명주기는 다음 세 상태를 권장한다.

```text
DRAFT(편집 가능) → PUBLISHED(응답 수집, 수정 불가) → ARCHIVED(신규 수집 중지)
                         │
                         └─ 새 버전 복제 → DRAFT
```

배포된 설문을 직접 고치면 같은 문항 코드의 의미가 과거와 달라져 통계가 왜곡된다. 따라서 변경은 새 초안 버전을 만들어 검토 후 발행하고, 모든 응답에는 `survey_version_id`를 기록해야 한다.

## 4. 권장 화면 구조

### 4.1 설문 관리

설문명, 버전, 상태, 응답기간, 제출 건수, 최근 변경자와 변경시각을 목록으로 보여준다.

주요 기능:

- 새 설문 또는 기존 버전 복제
- 초안 편집·미리보기·검증
- 발행 전 변경사항 비교
- 발행·마감·보관
- 권한이 있는 사용자만 편집 또는 발행

### 4.2 설문 편집기

```text
┌──────────────┬────────────────────────────┬──────────────┐
│ 섹션·문항 목록 │ 선택한 문항 편집              │ 속성·조건       │
│ S. 적격성     │ 질문 문구                    │ 필수 여부       │
│ A. 기본정보   │ 도움말                       │ 응답 형식       │
│ B. 제품이력   │ 선택지                       │ 표시 조건       │
│ C. 골절       │ 모바일 미리보기               │ 문항 코드       │
└──────────────┴────────────────────────────┴──────────────┘
```

편집 대상:

- 섹션명, 문항명, 도움말, 필수 여부와 순서
- 단일선택, 다중선택, 숫자, 날짜, 짧은 글, 표, 반복 그룹, 파일첨부
- 선택지와 `기타` 입력 여부
- 앞 문항의 답변에 따른 표시·종료 조건
- 최소·최대값, 최대 선택 개수와 반복 입력 개수

문항 코드는 통계와 데이터 계약의 기준이므로 발행 후에는 수정할 수 없게 한다.

### 4.3 발행 검토

- 모바일·PC 미리보기
- 필수 문항과 선택지 누락 검사
- 도달할 수 없는 조건 분기 검사
- 이전 버전 대비 추가·수정·삭제 문항 비교
- 발행 승인자와 발행 사유 기록

### 4.4 설문 현황 대시보드

```text
┌ 전체 응답 ┐ ┌ 최종 제출 ┐ ┌ 제출률 ┐ ┌ 평균 작성시간 ┐
├──────── 기간별 제출 추이 ────────┬──── 연령대 분포 ────┤
├──────── 적격성·이탈 퍼널 ───────┼──── 응답 방법·지역 ──┤
├──────── 제품 섭취·중단 사유 ─────┼──── 골절 경험·부위 ──┤
└──────── 문항별 응답 분포·미응답률·필터·비교 ───────────┘
```

상단 공통 필터:

- 설문 버전, 제출일 범위, 조사 방법, 제출 상태
- 연령대, 지역, 제품 섭취 경험, 골절 경험
- 필터 조건과 표본 수를 화면에 항상 표시

### 4.5 문항 상세 분석

문항 하나를 선택하면 응답 분포, 미응답·모름 비율, 기간별 변화와 연령대·지역별 교차분석을 보여준다. 자유서술형은 원문 목록보다 분류·키워드 빈도를 먼저 제공하고, 원문 열람은 별도 권한과 감사로그를 요구한다.

## 5. 지표 정의

| 지표 | 계산 방법 | 현재 데이터로 가능 여부 |
|---|---|---|
| 전체 응답 세션 | `survey_submission` 전체 건수 | 가능 |
| 최종 제출 건수 | `status = SUBMITTED` | 가능 |
| 제출률 | 최종 제출 / 전체 응답 세션 | 가능 |
| 평균 작성시간 | `submitted_at - created_at` | 조건부: 최초 서버 저장 이후 기준 |
| 연령 | 설문일 기준 생년월일의 만 나이 | 가능 |
| 연령대 분포 | 55~59, 60~64 등 구간별 제출자 수 | 가능 |
| 적격 제외율 | 적격성 문항에서 제외 조건에 해당한 비율 | 가능 |
| 단계별 이탈률 | 단계 진입 대비 다음 단계 이동 비율 | 불가: 단계 이벤트 추가 필요 |
| 문항별 응답률 | 유효 응답 / 해당 문항 노출 대상 | 조건부: 노출 여부 기록 필요 |
| 제품·골절·식품 분포 | 각 선택지 또는 반복 항목별 건수·비율 | 가능 |
| 버전 간 비교 | 동일 문항 코드의 버전별 분포 비교 | 버전 식별자 추가 필요 |

비율은 반드시 분모와 표본 수 `N`을 함께 표시한다. 서로 다른 설문 버전을 합칠 때는 문항 코드와 선택지 의미가 같은 경우만 비교한다.

## 6. 권장 데이터 구조

### 1단계: 현재 설문을 유지한 안전한 확장

- `survey_definition`: 설문 식별자와 이름
- `survey_version`: 버전, 상태, 발행시각, 원본 스냅샷
- `survey_question`: 문항 코드, 섹션, 문구, 형식, 필수 여부, 순서
- `survey_question_option`: 선택지 코드, 표시 문구, 순서
- `survey_question_condition`: 표시·종료 조건
- `survey_submission.survey_version_id`: 응답 당시 버전 고정
- `survey_progress_event`: 단계 진입·완료 이벤트
- `admin_audit_log`: 편집·발행·조회·다운로드 기록

기존 정규화 응답 컬럼은 그대로 유지하고, 먼저 문구·선택지·조건 정의만 버전 관리한다. 현재 기능을 깨뜨리지 않고 관리자 편집기를 도입하기 가장 안전한 방식이다.

### 2단계: 임의 문항 추가가 필요한 경우

`survey_answer(submission_id, question_id, answer_json)` 형태의 범용 응답 저장소를 추가한다. 다만 임상·연구 지표에 사용하는 핵심 문항은 타입과 단위가 명확한 정규화 컬럼 또는 집계용 Read Model로 변환해야 한다.

## 7. 관리자 API 초안

관리자 인증과 RBAC를 먼저 구현한 뒤 다음 API를 노출한다.

- `GET /api/v1/admin/surveys`
- `POST /api/v1/admin/surveys/{surveyId}/versions`
- `PUT /api/v1/admin/survey-versions/{versionId}`
- `POST /api/v1/admin/survey-versions/{versionId}/validate`
- `POST /api/v1/admin/survey-versions/{versionId}/publish`
- `GET /api/v1/admin/analytics/summary`
- `GET /api/v1/admin/analytics/questions/{questionCode}`

관리자 API를 인증 없이 추가해서는 안 된다.

## 8. 개인정보·통계 보호

- 관리자 로그인, 역할별 권한과 조회·다운로드 감사로그를 필수 적용한다.
- 생년월일은 화면에 그대로 노출하지 않고 서버에서 연령대로 변환한다.
- 표본이 적은 교차집계는 숨김 처리한다. 초기 기준은 `N < 5` 비공개를 제안하지만 연구·개인정보 담당자가 확정해야 한다.
- 원시 응답 다운로드는 별도 권한, 사유 입력과 워터마크를 적용한다.
- 대시보드 캐시나 로그에 연락처·생년월일·파일명을 남기지 않는다.

## 9. 구현 순서

1. 관리자 인증·RBAC·감사로그 — **기본 구현 완료**
2. 현재 고정 설문 기준 집계 API와 읽기 전용 대시보드 — **기본 구현 완료**
3. 설문 정의·버전·문항 테이블과 초안 편집기
4. 미리보기·검증·발행·버전 비교
5. 단계 이벤트와 문항 노출 기록
6. 교차분석·내보내기·소수집단 보호

대시보드를 먼저 읽기 전용으로 제공하면 현재 수집 데이터로 지표의 유용성을 검증한 후 편집기와 범용 응답 모델을 확장할 수 있다.
