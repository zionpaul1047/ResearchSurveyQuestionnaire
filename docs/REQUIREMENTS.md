# 요구사항 및 구현 범위

## 1차 MVP 목표

연구대상자가 모바일 또는 PC에서 복잡한 건강 설문을 작성하고, 중간 내용을 저장한 뒤 최종 제출할 수 있는 실행 가능한 기본구조를 제공합니다.

## 구현된 기능 요구사항

### 연구대상자

- 필수 연구 참여 동의
- 답변에 따른 적격·부적격 판단
- 일반정보 및 신체정보 입력
- 조사 방법·조사일·응답 확인용 연락처 입력
- 여성호르몬 치료 이력에 따른 A7-1 조건부 입력
- 제품 섭취 여부에 따른 제품 상세 표시
- 제품 최초 섭취 시점·이유·중요도·중단 이력 입력
- 제품 이력 자유 추가·삭제
- 골절 경험에 따른 상세 문항 표시
- 골절 이력 최대 3건 추가·삭제
- 제품 섭취자에게만 골절-제품 시점 관계 표시
- 식품별 섭취빈도와 1회 섭취량 입력
- 브라우저 자동 임시저장
- 서버 임시저장
- 최종 제출 및 제출번호 표시
- 제품·구매 증빙 이미지 업로드
- 원본 식품표의 쌀밥·잡곡밥·콩밥 3개 응답

### 서버

- 신규 임시 제출 ID 발급
- 임시 제출 수정
- 최종 제출 시 전체 필수값 재검증
- 제출 완료 이후 수정·재제출 차단
- 파일 Content-Type·시그니처와 10MB 용량 제한
- 파일 SHA-256 기록
- 제품·골절·식품 반복데이터 분리 저장
- Flyway 기반 스키마 이력관리

## 이번 단계에서 제외된 기능

- 대상자 인증과 문자 발송
- 관리자 로그인 및 권한
- 관리자 응답 목록·상세 화면
- Excel 다운로드
- 연구소·협력업체 API 또는 DB 연계
- 전송 실패 자동 재시도
- 개인정보 컬럼 암호화
- 악성파일 검사
- 자동 보관기간·파기
- 설문 문항을 자유롭게 만드는 설문 빌더
- 제공 원본에 없는 S5~S8, B7~B9, B11, D~G 문항

## 원본 정합성 원칙

- 제공 원본에 있는 문항만 확정 기능으로 구현합니다.
- 빠진 문항 번호는 내용을 추측하지 않고 `미확정`으로 기록합니다.
- B12 진입 조건처럼 선행 문항이 없는 분기는 최종 설문 원본을 받은 뒤 확정합니다.
- 식품섭취빈도는 임의 확장하지 않고 제공 표의 3개 항목만 최종 제출 필수값으로 검증합니다.

## 비기능 기본값

| 항목 | 기준 |
|---|---|
| 화면 | PC·모바일 반응형 |
| 전체 대상자 | 약 2,000명 가정 |
| 첨부 형식 | JPG, PNG, WEBP |
| 첨부 제한 | 파일당 10MB |
| DB | PostgreSQL 16 |
| Java | Java 17 |
| 배포 | Docker Compose 개발 구성 |

5. 개인정보 보관·파기 기간
6. 관리자 역할과 접근 범위
7. 연구소·협력업체 연계 방식과 데이터 범위
8. 운영 인프라, 도메인, 인증서, 백업 정책
